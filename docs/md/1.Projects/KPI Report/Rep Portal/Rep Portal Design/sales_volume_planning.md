# Sales Volume Pricing — Planning & Reference

**Tool:** Volume Price Report (`volume-price-report.html`)  
**Last updated:** 2026-06-11  
**Data script:** `rebuild_clients.py`

---

## Purpose

A rep-facing tool that shows, for any selected customer, what they are currently paying for each product versus the structured tier pricing. The goal is to help reps identify upgrade opportunities and support conversations about volume-based pricing.

## How to Refresh Data

Run from the `Rep Portal Design` folder:

```powershell
python rebuild_clients.py
```

This:
1. Reads all 5 rep sheets from the Call Cycle Audit xlsx (rows 4+ = data)
2. Reads `Sales_Invoices_YTD.CSV` — net volumes (INVOICE +qty, CRNOTE −qty) per account per product for the last 3 months
3. Picks the most recent invoice line price per account per product as `lastPrices`
4. Writes the `CLIENTS` array back into the HTML
5. Regenerates `Volume Price Report.xlsx`

Run whenever `Sales_Invoices_YTD.CSV` is refreshed with new invoice data.

```js
  name: "Customer Name",

  volumes: {             // net units sold, last 3 months
    "Decor 20L": 40,
    "High Gloss 5L": 12,
    // ...
  },
  lastPrices: {          // most recent INVOICE line price > 0
    "Decor 20L": 285.00,
    // ...
  }
}
```

## Tier Pricing Structure

Three tiers per product. Tier 1 is the entry price; each higher tier is a volume discount.

| Tier | Description | Approx discount vs T1 |
|---|---|---|
| T1 — Entry | Base list price, no volume commitment | — |
| T2 — Mid Volume | Moderate volume threshold | ~8% below T1 |
| T3 — High Volume | High volume threshold | ~15% below T1 |

Tier prices and quantity thresholds are hardcoded in the HTML under `const TIER_DATA` (one entry per product with `t1`, `t2`, `t3` price objects each containing `price` and `minQty`).

**Discount columns shown in the table:**
- `T1→T2 %` — percentage drop from T1 to T2
- `T2→T3 %` — percentage drop from T2 to T3  
- `T1→T3 %` — total discount from entry to highest tier

## Report Layout

### Filters (always visible)
- Rep → Region → Customer (cascading)
- Customer badge shows selected name

### When no customer is selected
- Prompt showing count of available customers for current filter

### When a customer is selected — Summary Strip
- Customer name, rep, region
- Count of products qualifying for T3 / T2
- Count of products where customer is paying above T1
- Count of products with price data

### Price Table (one row per product, grouped by category)

| Column | What it shows |
|---|---|
| Product | Name + category group header |
| Avg Price (3M) | Customer's last invoice price; ▲ red if above T1, ▼ green if below, with % delta |
| T1 Price | Entry price + minimum qty |
| T1→T2 % | Discount to unlock T2 (green ↓) |
| T2 Price | Mid-volume price + qty threshold |
| T2→T3 % | Incremental discount to T3 (green ↓) |
| T3 Price | High-volume price + qty threshold |
| T1→T3 % | Total discount T1 to T3 (amber ↓) |

The column for the tier the customer currently qualifies for (by their 3-month volume) is highlighted green.

## Known Limitations

- **"Avg Price (3M)"** label is technically the *most recent single invoice price* per product, not a true 3-month average. The YTD CSV does not have enough granularity to calculate a weighted average without aggregating by date range. The label is accurate enough for rep conversations.
- **425 accounts** reflects the Call Cycle Audit as at 2026-06-01. 16 rows in the xlsx are header/summary rows and are filtered out automatically by `rebuild_clients.py`.
- Credit notes (CRNOTE type) reduce net volume — floor is 0, negative net always becomes 0.
- Accounts with no invoice activity in the 3-month window will show zero volumes and no last prices.
